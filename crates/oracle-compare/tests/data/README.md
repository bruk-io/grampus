# Comparator test fragments

These G-code fragments are hand-written, not captured from a real oracle run: this task (part 1
of plan step 5) must build and pass its tests on a machine with no oracle binary and no libslic3r
build, so it never invokes the oracle and commits no file a run of it produced. Task
`09-comparator-gcode-levels` (part 2 of step 5) holds to the same rule for its own fixtures below.

The plan's "pair taken from two real runs of Step 2" has arrived: it is `tests/data/real/`,
committed by task **`10-comparator-json`**, the last part of step 5, which depends on
`04-oracle-slice` and so has the oracle available.

## Task 10's fixtures (JSON, and the real pair)

| Directory | What it covers |
|---|---|
| `json_settings_identical/` | Two byte-identical `settings.json` fragments: `L0`. |
| `json_settings_pipeline_plugin/` | Differ only in `slicing_pipeline_plugin`: `none` naming that key with the allowance off, `L1` with it on. |
| `json_settings_other_key/` | Differ in `layer_height` (an unrelated key), with the allowance tried both off and on: `none` naming `/layer_height` either way — the allowance never excuses a different key. |
| `json_statistics_generator/` | Differ only in `generator`: `L1`, not `L0`. |
| `json_statistics_other_key/` | Differ in `summary.time`: `none` naming `/summary/time`. |
| `json_malformed/` | `a.json` is truncated (not valid JSON) and `b.json` is: reported as `none` with the first raw differing byte, for both `--settings` and `--statistics`, never a panic. |
| `real/run1/`, `real/run2/` | **The real pair.** Two runs of `just oracle-slice vendor/OrcaSlicer/tests/data/frog_legs.obj base-fff --export-settings --export-statistics` against the pinned v2.5.2 oracle (each run ≈4.5s). Each `runN/` holds that run's `settings.json`, `plate_1.statistics.json`, and `plate_1.gcode` truncated to its header block plus one full layer (the first 3226 of 20894 lines, cut immediately before the second `; CHANGE_LAYER`, identically on both sides). **Measured, not assumed:** `diff`/`cmp` found all three artifacts — the two full `settings.json`, the two full `plate_1.statistics.json`, and the two full `plate_1.gcode` (568128 bytes each) — byte-identical between the two runs; `tests/json.rs`'s `real_settings_pair_reaches_l0` and `real_statistics_pair_reaches_l0`, and `tests/levels.rs`'s `real_gcode_excerpt_pair_passes_every_level`, assert exactly that measured outcome (`Level::L0`, every G-code level passing) rather than a value picked in advance. |

## Task 08's fixtures (L0, L1)

| Directory | What it covers |
|---|---|
| `identical/` | Byte-identical pair: every level passes once L2-L4 are evaluated (task 09). |
| `generated_by/` | Differ only in the `; generated by ` timestamp line: L0 fails, every other level passes — the line is comment-only, so it never reaches L2's tokens or L3/L4's move model. |
| `plugin_armed/` | One side carries a `slicing_pipeline_plugin` config line the other lacks (the armed-against-unarmed shape Step 8's dumper produces): L0 fails, every other level passes, for the same reason. |
| `model_label/` | Differ in a `; model label id: ` line and in both the start and stop `..., unique label id: N` lines: L0 fails, every other level passes — object labels are not an L4 grouping dimension and not part of L3's per-move comparison. |
| `one_coordinate/` | Differ in one `G1` coordinate, which no normalisation rule touches: every level fails (the literal, the value, the move and every aggregate it feeds all disagree). |
| `unrelated/` | Two unrelated files: every level fails from the first byte. |

## Task 09's fixtures (L2, L3, L4, the tolerance reader)

| Directory | What it covers |
|---|---|
| `comment_text/` | The only difference is a trailing inline comment's text: L0 fails, L2 passes (comments contribute no tokens at all). |
| `coordinate_literal/` | `X10.0` vs `X10`: L2 fails (different literal text), L3 passes at exact tolerance (the same parsed value). |
| `small_drift/` | One `X` coordinate moved by `0.001`: L3 fails at exact tolerance; `manifest/tolerance.tsv`'s `Foo/Bar.cpp` row declares `0.01 mm` with a reason, and L3 (and L4) pass against it. |
| `inserted_move/` | `b` has one extra move appended after two moves identical to `a`'s: L3 reports the move-count difference (2 vs 3) at the first index the shorter side has none, naming that move's layer, role and (absent) object. |
| `reordered_moves/` | Two extruding moves to colinear, origin-symmetric points, in opposite order on each side: every per-move X value disagrees (L3 fails) but every L4 aggregate — move count, extruded length, E delta, bounding box, travel distance, layer count — comes out exactly equal (L4 passes), proving the two levels are evaluated independently. |
| `layer_count_mismatch/` | `b` has one extra `; CHANGE_LAYER`/`;Z:` pair with no move after it: every other aggregate matches, but the whole-file layer count differs (1 vs 2) — the layer boundary the localisation found, not a count derived from which layers happen to carry a move. L4 fails naming layer 1 as present only in `b`. |
| `tag_spellings/` | `bambu.gcode` and `compatible.gcode` carry the same single move localised with the Bambu (`; CHANGE_LAYER`, `; Z_HEIGHT:`, `; FEATURE:`) and non-Bambu (`;LAYER_CHANGE`, `;Z:`, `;TYPE:`) tag spellings respectively; both parse to the same layer/Z/role. |
| `localisation/fragment.gcode` | One file, not a pair: asserts a named move's layer, role and object through the parser's public API, across an object-label start/stop and a layer change. |
| `manifest/tolerance.tsv` | A fixture manifest with a `path`/`tolerance`/`comparison function` header: `Foo/Bar.cpp` (valid, with a reason), `Foo/Baz.cpp` (a value with no reason — refused), `Foo/Qux.cpp` (both cells empty — defaults to exact, silently), `Foo/NoTolFn.cpp` (an empty tolerance cell but an unimplemented `comparison function` — refused; proves the function cell is checked independently of whether a tolerance value is present). |
| `manifest/no_tolerance_column.tsv` | A fixture manifest with neither a `tolerance` nor a `comparison function` column, for the "table has no such column" error path. |
| `config/tolerance.md` | A stand-in for the `docs/ORACLE.md` configuration table `04-oracle-slice` will add (which does not exist yet — see `tests/tolerance.rs`'s test against the real document): `basic_pla` (valid, with a reason) and `no_reason` (a value with no reason — refused). |
